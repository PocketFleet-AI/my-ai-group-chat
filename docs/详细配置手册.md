# 详细配置手册

[返回中文首页](../README.zh-CN.md) | [English Guide](Detailed-User-Guide.md)

本手册说明当前产品的实际配置流程。公开安装包仍须通过干净 Windows 环境验收后发布；仅下载此仓库的扩展源码，不能编译或替代闭源桌面调度引擎。

## 一、准备环境

- Windows 10 / Windows 11，64 位。
- Telegram 账号、协作群，以及你创建的 Bot。
- 网页席：Chrome、配套浏览器扩展、已登录的 AI 网页。
- 代码席：对应 IDE 或受支持的 CLI，已完成安装和鉴权。
- 电脑保持唤醒、联网，能够访问 Telegram 和所选 AI 服务商。

其他 Chromium 浏览器需独立验证兼容性。网页模式不要求模型 API Key；CLI 可能使用账号登录、API Key 或其工具自身的鉴权机制，并非统一免鉴权。

## 二、安装桌面端

正式发布后，从 [GitHub Releases](https://github.com/PocketFleet-AI/my-ai-group-chat/releases) 下载并完整解压桌面包，运行 `PocketFleet.exe`。

保留包内配套文件，包括 `pfExtract.exe`，不要只复制主 EXE。桌面端用于管理连接和席位；会议在 Telegram 群内进行。

## 三、创建 Bot 与绑定群组

1. 在桌面端进入 **Telegram Setup / 创建 AI Bot**，通过 **BotFather** 为每个 AI 席位创建对应 Bot。
2. 将每个 Bot 的 Token 粘贴到卡片中，完成验证。Token 应像密码一样保管。
3. 创建 Telegram 群，将相应 Bot 加入。
4. 进入 **Configure Group / 配置群组**，必要时点击开始监听，再用自己的 Telegram 账号在群里发送 `/PocketFleet`。
5. 在识别出的群卡片中选用目标群，点击 **Use This Group / 使用此群**。

先配置 1 个 Bot 即可继续设置；首次验证多 AI 协作时，建议准备两个可用 AI 席位。Bot 验证通过不代表它绑定的 AI 当前在线。

## 四、连接网页 AI

控制台当前提供 ChatGPT、DeepSeek、Claude、Gemini、Qwen、Grok、豆包的接入卡片。

1. 通过桌面端 **Web Store** 入口安装扩展，或将发布包附带的扩展文件夹在 Chrome 开发者模式下加载。
2. 打开 **Connect Chat AI / 连接对话 AI**，点击 **Copy Pairing Token / 复制配对令牌**。
3. 将配对令牌粘贴到扩展弹窗并保存。不要在公开截图、Issue 或其他电脑间共享它。
4. 打开并登录相应 AI 网页，保持目标标签页可用，为每张卡片分配相应 Telegram Bot。

已有订阅、登录状态、用量额度及服务商限制仍然适用。网页改版可能需要更新适配规则。

## 五、连接代码 AI

控制台当前列有 Antigravity、OpenAI Codex、WorkBuddy、Claude Code、Cursor、GitHub Copilot、OpenCode、Qoder、DeepSeek Harness。

| 模式 | 使用方式 | 前提 |
|---|---|---|
| **IDE** | 向目标 IDE 的任务会话投递；UI 自动化可能切换前台焦点。 | 对应客户端和会话已打开，窗口恢复显示，不最小化到任务栏。 |
| **CLI** | 通过独立本地命令行任务轨执行，无需切换桌面焦点。 | 对应受支持 CLI 已安装、登录，并为席位配置正确工作目录。 |

不同工具可用模式不同，不能因卡片存在就认定两种模式均已就绪。模型和工具费用独立于本产品授权。

**上下文边界**：网页或 IDE 连接使用选定会话可用的上下文，不代表跨工具导入全部历史。CLI 会议轨独立于 IDE 原会话；能否只读查阅 IDE 背景取决于适配器、路径和实际可读记录，不能假定已经继承或读懂。

派工不授予额外文件系统、终端或账号权限。工具审批和成果验收仍由用户掌握。

## 六、选择席位并开会

1. 进入 **Launch Council / 发起会议**，勾选本次参会席位。
2. 点击 **Attendance Check / 出席检查**，确认目标 AI 可用。
3. 确认会议监听已运行，打开目标 Telegram 群并发送 `/meet`，按提示选择主持、参会者并确认目标。
4. 完成后使用 `/meetover` 闭会。

当前文档流程仍要求人在群里发送 `/meet`；打开群组不等于已经自动提交命令。尚未验收的新按钮行为不作为已实现能力宣传。

桌面程序可以留在托盘运行；选择 **Quit PocketFleet** 则会退出。手机负责发指令与读回复，不运行 Windows 引擎，电脑睡眠或离线时无法继续正常调度。

## 七、状态与授权

**已配置、已绑定、在线、已勾选参会、正在执行不是同一状态。** 绿色绑定卡片不能代替出席检查；保存了多个连接，也不代表许可允许这些 AI 同时参会。

Free 允许同时启用 2 席，Solo 4 席，Team 6 席，Ultra 12 席；限制针对参与协作和任务调度的启用席位，不限制已保存的 AI 配置数量。人类不计席位，所有档位使用相同安装包。Free 永久免费，付费授权有效期均为 12 个月。

体验码自签发日起 30 天有效，晚导入不会重新起算。当前设置向导尚无可见的授权码输入控件，发放及导入方式将随体验版公布并验证，不应假定已经存在激活页面。到期回落 Free，保留配置及历史；取消勾选超额参会者即可继续。不要在公开反馈中粘贴授权码。

Free 和商业权益不强制扩展心跳，但网页席仍需要扩展传输消息。授权依赖和通信依赖不是一回事。

## 八、常见排障

| 现象 | 检查项 |
|---|---|
| 扩展连不上 | 桌面程序是否运行，扩展中是否保存本机当前配对令牌。 |
| Bot 已验证，但 AI 离线 | AI 是否登录、目标会话是否可用，出席检查是否通过。 |
| IDE 找不到输入框 | 打开目标任务会话，恢复窗口；不要对提交结果不确定的任务连续重发。 |
| CLI 不能执行 | 工具是否安装、鉴权是否有效、该模式是否支持、工作目录是否正确。 |
| 手机派工没有回应 | 电脑是否睡眠或断网，桌面监听和对应 AI 工具是否仍运行。 |
| 到期后提示超限 | 取消勾选额外席位，不必删除已保存连接。 |

如需反馈，请提供应用及扩展版本、Windows 版本、AI/模式、复现步骤及脱敏错误。移除 Bot Token、配对令牌、授权码、个人路径和私密对话；不要上传签发私钥。

## 九、技术架构与隐私

本地桥主要控制端口为 `127.0.0.1:18765`；`18766` 用于直接任务传输，`18767` 用于开发者定位器工作台。配对令牌由本机生成，发行包不预置全体用户共用的有效秘密。

本地桥这一跳走回环，不代表整场会议只在本机。Telegram 会接收群内任务与回复；AI 服务商按各自政策处理内容；IDE/CLI 还可能按自身配置访问外部工具。

桌面端本地保存配置、诊断日志及会议记录。浏览器适配规则通过 Cloudflare Worker 下载并校验签名；请求不包含对话文本，但会产生 IP、HTTP 报头等正常连接元数据。

[完整架构与隐私说明](ARCHITECTURE.md)。本产品不提供模型订阅，不绕过服务商额度、工具审批或网络限制。

## 十、自行构建浏览器扩展

安装 Node.js 后执行：

```bash
git clone https://github.com/PocketFleet-AI/my-ai-group-chat.git
cd my-ai-group-chat
npm run build
npm run check
```

产物为 `browser-extension/content_bundle.js`。检查验证 38 个源代码段组装到同一闭包，不是完整会议端到端验收。

公开扩展可独立构建，不包含闭源 Go/Wails 桌面程序，也不自动授予商业权益。扩展和公开接口规范采用 [Apache 2.0](../LICENSE)，品牌与桌面内核边界见 [NOTICE](../NOTICE)。
